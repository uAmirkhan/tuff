# Архитектура — TUFF

Документ описывает то, что уже построено, и решения, которые связывают руки следующим виткам.
Подробная карта кода — `research/karta-proekta.md`.

## Слои и правило зависимостей

```
physics/   решатель: частицы, связи, контакт с отрезками   — не знает об игре
   ↑
game/      тело, способности, враги, боссы, слияние, цикл  — не знает о рендере
   ↑
render/    сцена PixiJS, камера, фон
main.ts    склейка: ввод → игра → отрисовка
```

Правило из `CLAUDE.md`: симуляция запускается **без экрана**. Поэтому вся физика и вся
игровая логика проверяются прогонами в тестах, а браузер нужен только для ощущения,
производительности и настоящих нажатий.

Сопутствующие: `level/` (формат, загрузчик, валидатор, Tiled), `input/`, `audio/`, `meta/`
(сохранение, локализация, аналитика), `platform/` (адаптеры площадок).

## Решения, которые нельзя нарушать

1. **Данные частиц и связей — типизированные массивы.** В такте нет выделения памяти.
2. **В симуляции нет `Math.sin`, `Math.cos`, `Math.pow`, `Math.random`.**
3. **Число в коде вне `src/game/config/` — это баг.** Все калибровки живут в конфигах.
4. **Порядок операций такта зафиксирован.** Новая подсистема встаёт в этот список до слияния.
5. **Чистая комната.** `npm run cleanroom` зелёный, имя референса не встречается нигде.

## Как устроен кооператив

Ключевое устройство — **`Igra.zhizni`: жизнь на каждое тело игрока** (жар, принудительная
Корка, заряды инея, причина урона). Нулевая жизнь всегда героя, поэтому `igra.zhar` и
`igra.korkaSredy` остались видом на неё, и ни интерфейс, ни старые тесты о списке не знают.

- Плиты, зоны среды, поток, рычаги, сбор, горны и враги считаются по **всем** телам игрока.
- Выход требует **обоих**: расстояние берётся по дальнему.
- Слияние (`game/sliyanie.ts`) — связи между ближайшими частицами колец плюс **каркас**
  (сетка «частица i тела А к частице i тела Б»). Связи берутся из пула, выделенного один раз:
  решатель не переиспользует слоты, и цикл слияние-разделение иначе исчерпал бы их за минуту.
- Топологического объединения контуров нет сознательно: контур считает площадь обходом по
  кольцу, склейка двух колец дала бы самопересекающийся многоугольник.
- Камера на двоих вынесена в `render/kamera.ts` чистой функцией и потому покрыта тестами
  без запуска PixiJS.

**Что кооператив уже стоил и чего ещё нет.** Движок был написан вокруг одного тела, и
разведение «герой» и «тело» оказалось дороже самой физики. Не сделано: деление экрана
(камера умеет только сообщить, что тела не влезли), меню выбора режима, остывание по
расстоянию.

## Известные ограничения, влияющие на дизайн уровней

Замерено, лежит в вики Khan'а, повторено здесь потому, что связывает руки:

- **Вязкость не липнет ко льду.** По базальту, металлу и хрупкому одиночка залезает на любую
  высоту, по льду не поднимается вовсе.
- **Ворота на достижимости слиянием не защищаются.** Вертикаль закрывает живая ступень
  (тела забираются друг по другу), горизонталь закрывает Выброс. Это свойство персонажа.
- **Слитая пара не проходит щель ≤0,8** ни при какой толщине перегородки.
- **Слитую пару не рвёт поток** никакой силы; несклеенных разносит уже при силе 10.
- **Встречный ввод роняет ход слитой пары до нуля.** Партнёр останавливает её одной клавишей.

## Сетевого кода нет и не будет в этом релизе

Физика на числах с плавающей точкой, детерминизм между машинами не гарантирован. Локальный
кооператив плюс Steam Remote Play Together закрывают задачу за ноль часов разработки.
